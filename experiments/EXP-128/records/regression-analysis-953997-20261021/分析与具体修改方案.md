## 1. 结论与证据边界

193个尺寸、z2d与d2z，共386项对照；其中60项当前中位数更慢，39项中间50%区间完全错开且当前更慢，21项区间重叠，应标记“差异不明确”。区间错开只是本轮观察，不能替代多次独立实验的统计结论。全部逐次样本保留，未剔除慢点。

对照是EXP125的二次幂优化版，不是官方基线。60项中22项保持相同CC分解，38项在旧版分解表没有CC条目；后者按旧选择器源码应走转置分解。这38项的旧路径属于源码推断，未补做旧版设备追踪；它们同时包含计划选择变化，不能全部解释为融合本身的损益。

优先解决两类共用机制：列阶段逐寄存器重复写出分支造成的编译溢出；正变换行阶段不必要的共享存储输入中转。另按能力保留已有二次幂专用融合。142688点双向退化和部分逆变换行阶段退化仍需阶段证据，不能据现有资料声称已全部找到主因。

### 具体改法

将列类别判断移出寄存器写出生成循环，生成三段完整写出体，共用一份地址及写出辅助生成函数；加载侧的列有效性判断也移至生成循环外，与已编译组合原型保持一致。单独对照尚未证明加载侧合并有资源收益。原有寄存器清零与缓存同步保持在条件外：

```cpp
if (column == 0)
    emit_native_stores(first_boundary_component);
else if (column == Q)
    emit_native_stores(last_boundary_component);
else if (column < Q)
    emit_native_stores(interior_complex_value);
```

这是生成器结构示意，`emit_native_stores`在主机生成代码时展开，不是增加设备调用。保留原`pass_io`的有效线程和尾项保护；首末边界继续分别写打包复数的两个独立实数分量，内部列仍写同一个复数地址。操作集合、索引、浮点运算和每线程写出顺序不变，不增加共享存储和同步，不接触用户输入回调。把统一规则应用于全部折叠列内核，避免列长289或某些N的白名单。

相位递推复用`/public/home/zhangkewei/zr/rocm-libraries-rocm-7.2.2/projects/rocfft/library/src/device/generator/stockham_gen_cc.h:622`至`:723`已有机制。设同一末级蝶形的相位指数依次为`(u0+w*h)*b`，先查询起始相位与步长，再逐项相乘递推。17路蝶形的独立多阶查询从17次变为2次，增加16次串行复数推进；可减少查表和临时值，也引入依赖链与舍入累积。不是删掉跨段旋转因子。

策略仅扩展到新折叠列角色，按末级基数和相位查表阶数选择；现有普通内核规则保留。首先覆盖宽末级基数、多阶查表且离线资源改善的配置，再由整类设备性能决定默认策略，不能按慢尺寸名单选择。现有8项17路编译对照支持该候选，但不能据此承诺其他基数同样加速。

正确性依据是单位根指数的加法关系，沿用原`TwiddleMultiply`方向和共轭语义；链长随蝶形宽度而不是N增长。27240个相位点的主机模型最大绝对差约1.42×10⁻¹⁵，只是辅助证据，不能代替完整设备变换的严格小于10⁻⁹校验。

新增控制策略须纳入生成器规格和运行时缓存身份；建议统一提升`cc_local_v1`命名版本，记录递推策略，避免旧缓存掩盖修改。分支合并本身不需要再建一套设备算法。

### 具体改法与成本

为`FoldedSpectrumRows`增加原生首级映射能力判断，依据因子乘积、线程分工、覆盖完整性及尾部保护决定寄存器加载，替代当前二次幂限制。能力函数放在`real_block_io.h`等既有策略位置，生成器消费结果，不在多处复制N判断。寄存器／共享存储选择继续进入实际生成代码和缓存名。

从生成代码层面可去掉一次完整复数共享存储写入、读出和`reload_input`里的两次同步。行长289、每块7行时，逻辑搬运为每块64736字节；行长343、每块5行时为54880字节。共享存储仍供FFT及输出使用，峰值分配不会因此自动下降，不能据此声称占用减半或驻留块数必然增加。

全局输入元素数不变，但线程读取次序变化，可能降低合并访问效率；相位查询与全局加载重叠、寄存器压力也可能改变。121和1331行的资源略增，就是需要保留原后端并以整类性能验收的原因。以上字节数是逻辑共享存储量，不是设备实测事务或端到端加速预测。

该改法针对d2z的正变换行。z2d逆变换还需要配对输入；奇数线程分工的镜像伙伴可能跨波前，不能直接放宽`CanRegisterPre`来套用同一实现。行长289的逆变换退化尚不能由正变换寄存器候选解释或保证解决。

验证清单同步登记各配置应命中的具体后端，接受计划预先指定的旧式融合或新式融合角色，不能仍强制所有尺寸必须出现新角色编号，以免正确执行旧式融合却被登记错误阻塞。

## 5. 其余退化逐类处理

行长289在15个尺寸中，z2d有14项中位数更慢，d2z有12项更慢，属于值得继续处理的整类。已检查的行内核没有离线溢出，不能把列阶段的172溢出结论复制给行阶段。部分对照又伴随转置到CC的计划变化，应分开诊断。

前处理方案还将首段逻辑列变换数从Q增加到Q+1；若与同分解的Q列算法比较，变换数量增加1/Q，Q=121约为0.83%，Q=289约为0.35%。实际成本取决于尾块和有效线程，不能当作整个变换的耗时百分比。这项结构性代价确实存在，但单靠变换数量难以解释多倍退化；寄存器溢出、线程分工、相位与局部交换必须分别核对。当前后处理没有增加复数FFT数量。

142688点为208×343，两方向均退化，且旧新使用相同CC分解：z2d为33.20→45.44微秒，d2z为32.88→40.16微秒。行长343的其他多数尺寸却加速，例如65856点两方向均加速。当前只能确认直接寄存器输入有可行候选，尚不能证明它是142688双向退化的共同主因；需要比较两段耗时、实际资源及访问事务。

67760、81312点z2d属于121行；94640点z2d属于169行；191664点z2d属于1331行。优先检查逆行阶段输入配对、双分量写出和相位成本。已有69938点121行追踪仅支持行阶段成本不低，不能作为这四项的独立因果证据。

81920点双向、86016及106496点d2z的区间错开差异约0.32～0.96微秒。通用行输出固定经共享存储、索引重排与原有普通SBRC的差异是候选原因；目前没有足够分段证据。另21项区间重叠，保留结果，下轮同类对照再观察，不逐尺寸加开关。

不要直接把`StockhamKernelCCRealRows`的`direct_store_from_reg=false`改为true：当前线程持有的结果映射与原生合并写出映射不同，必须先证明所有权及排列，且奇偶列长的双分量输出配对不同。也不建议全局切换半共享存储、为慢尺寸改分解、或回退转置路径来宣称已解决退化。

## 6. 实施顺序、验收与恢复

1. 先改通用列写出结构和宽基数相位策略。两项在编译阶段独立检查，确认组合消除整类溢出，再进行设备数值和实际路径验证。列长289的8项全部保留为类型覆盖，并以其他列长、相位阶数和尾块作为控制。
2. 单独提交正变换行寄存器加载策略，便于区分收益。覆盖行长121、169、289、343、1331，以及原本默认寄存器的二次幂／对齐控制；覆盖奇偶C和尾行。
3. 通过能力选择保留旧二次幂融合；预先明确每个验证配置对应后端。单位与非单位缩放的选择由主机策略核对，当前设备性能仍按默认输入和默认缩放。
4. 对尚未定位的类型补最小阶段诊断：Q=289选奇偶C及尾块；208×343与96×343对照；普通CC选81920；逆行选Q=121与1331。诊断必须含同类已加速控制，既看两段耗时，也看私有访存、实际寄存器和全局／共享事务。若仍要分离分解与融合成本，可加诊断用同CC分解未融合对照，不能把EXP125不同计划直接当成纯融合收益。
5. 遵循当前AGENTS：构建与验证分开；先1～2个代表烟测，再跑最小受影响路径矩阵，独立用例一次汇总全部错误。性能前仅检查数值正确及实际优化路径，不增加完整内存、回调或发布回归。性能仅测登记版本的默认选择，继续10次预热、30次计时、中位数和完整散点。提交任务后停止，等待用户检查。

生产候选按步骤保留独立提交和安装，保留本轮已验证安装；未取得设备数值与整类性能前，不覆盖已验收安装，不改稳定分支或标签。通过默认后端能力选择和独立构建恢复，不能以修改原始结果表代替恢复。

预期收益目前只能描述为“消除已证实的编译溢出”和“减少行输入中转”，不能可靠承诺百分比。设备对比还需确认编译器与离线结果一致、访存合并没有抵消收益、其他列／行长没有新增退化。
