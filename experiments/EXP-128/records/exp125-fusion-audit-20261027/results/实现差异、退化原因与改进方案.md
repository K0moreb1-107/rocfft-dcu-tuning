# EXP128与EXP125：融合实现、收益来源与退化原因

建议先做两项通用改进：按已知几何生成前处理输出，恢复后处理行端的大相位递推。前者已经在源码副本中消除了旧二次幂路径上的大量无效分支；后者补回了相位乘法移到行端后丢失的复用机制。两项均按几何和原生线程映射选择，不判断具体N。后处理列内交换仍有独立成本，不能指望仅恢复读取调度就全部消除。

当前大幅加速的总表混合了计划改变和融合；需要同一CC计划的未融合对照才能分别量化。已有数据能够确认净收益存在，也能够确认旧二次幂融合在通用化时丢失了一些有效实现细节。

本轮核对三个实际库：EXP125保留版1d745ec17f51、热力图第三版8da0abb02ae6、当前第四版965122a7e5bd；对应库校验值依次为243849fd7f03、f97365bba962、6b4a635fd1e2。第四版相对第三版只修改后处理行端的双寄存器分组及版本名称，没有改变列端或前处理。完整身份见“核对与证据口径.json”。范围仍为一维、双精度、批量一、非原位、偶数N≥65536。

## 1. 先把比较对象拆清楚

原热力图194个默认尺寸，EXP125已有32个CC尺寸，其中五个二次幂已经融合；另27个是CC但前后处理独立，162个原来不是CC。重新解析两版有效分解表，确认60项原映射全部保留，新表补充至222项，第三版和第四版的表相同。

|---|---:|---:|---:|---:|---:|

第四版在27个原CC尺寸中，z2d有24项中位数更低，d2z有25项更低；其中分布明确更快分别9项、11项。这里没有从非CC改为CC，不能把这些收益解释为路径切换。它们仍包含融合边界适配、加载方式等共同变化，不是某一条代码的单因素贡献。

162个原非CC尺寸的大幅收益包含计划变化。不能把其1.27倍左右的中位比值全部归于融合，也不能用它减去另一组中位比值，算出“计划贡献百分之多少”。两组尺寸不同，贡献也可能相互影响。

## 2. 两版已经共同省掉了什么

记M=N/2=CQ。普通未融合CC需要前／后处理加两段复数变换，主信号逻辑全局读写约48N字节；融合后约32N字节，内核数三变二。以上忽略端点小项，不是实际显存事务量。

EXP125的五个旧尺寸已经是两个内核，当前版也是两个。当前版相对EXP125没有再次获得“省一次完整全局写出及读回”或“再少一次启动”的收益。两版内部FFT规模也都接近半长，并没有谁误用了完整N点复数FFT。

前处理两版都做Q+1次C点逆变换，再做C次Q点逆变换；多出的那次C点逆变换是EXP125就有的，不能当成通用版新增退化原因。后处理两版都做Q次C点、C次Q点复数变换。

## 3. 前处理：数学结构接近，数据布局与输出代码明显不同

两版都先对折叠半谱做列逆变换，使用周期N相位，使每条末段行成为2Q点实数逆变换的局部半谱；在行内组合j与Q−j，再做Q点复数逆变换，最后把相邻实数合并写回。

| 细节 | EXP125 | 当前第三／四版 |
|---|---|---|
| 首段端点 | 第零列和第Q列各占一个复数槽 | 两个实数端点打包到一个复数槽 |
| 中间矩阵物理行距 | Q+8个复数 | Q个复数 |
| 末段输入 | Q+1个局部半谱复数 | Q个复数，首槽含两个端点 |
| 旧五尺寸的默认加载 | 波内交换后直接进入寄存器 | 同样是波内交换后直接进入寄存器 |
| Q=512小相位表读取 | 四项提前读取，跨成对计算复用 | 每对前读取，未沿用四项预取策略 |
| 写出安排 | 全部线程各负责一个分量和相邻两行 | 分实、虚两轮，保留对齐、有效行、标量／向量分类 |

需要纠正一个容易混淆的说法：EXP125每行使用Q+1个半谱元素，但物理行距实际为Q+8。其余七个槽是填充，不是每轮都传输的数据。当前版打包端点后，主信号逻辑读写比旧版少32C字节，临时容量少128C字节。以128K为例，分别为8 KiB和32 KiB；这远小于再省一整遍矩阵。

### 已确认的输出成本

本轮直接提取已通过验收的实际运行源码，使用同一离线编译参数比较。128K行端为：

| 编译指标 | EXP125 | 当前版 | 仅修改输出的源码副本 |
|---|---:|---:|---:|
| 整个内核静态指令 | 743 | 1021 | 720 |
| 向量整数指令 | 181 | 384 | 231 |
| 执行掩码／分支类指令 | 10 | 47 | 11 |
| 向量寄存器需求 | 66 | 66 | 66 |
| 最后同步之后的静态指令 | 102 | 433 | 另见汇编产物 |

原因具体落在`StockhamKernelPackedInverseRows::store_to_global`：虽然C、每块行数及整除关系在生成时已知，设备代码仍计算`min(R,C−first)`，保留首尾标量写出和频率尾部条件。对于列数为偶数、每块行数为偶数、整块覆盖的几何，这些分支本来就不会走到，但编译器没有从线程块编号推断出完整网格约束。

此外，当前版把实、虚分量分为两轮，轮内只有一半行槽负责向量写出。旧版把“分量”和“相邻行对”一起分配给线程，一轮让全部线程各完成一次向量写出。两者最终输出元素相同，设备端的分类、掩码和共享读取安排不同。

已有957127诊断中，128K前处理行端为EXP125的8.48微秒对通用第二版的12.16微秒；首段为10.40对10.88微秒。旧计数器中行端共享存储操作10240→13312，二级缓存读请求16820→16615，临时内存均为零。第二版行端后来已被简化，不能把这些旧耗时直接当作第四版耗时；本轮58份源码重新编译证明，当前输出适配层仍有上述明显额外工作。

因此，128K问题不是没有命中融合，也不是读取信号突然增多。输出安排增加了实际可消除的工作；它对当前退化的精确耗时贡献仍需源替换受控测量。

### 尚未定因的两项细节

删除Q+8填充改变了全局地址步长；Q=512没有保留旧的小表预取。这两项差异已经由代码确认，但没有与其他改动隔离的当前设备数据，不能把退化分别归于缓存冲突或预取消失。尤其128K的Q=256，不能用Q=512预取策略解释它。

## 4. 后处理：改变了配对位置，也丢失了原相位复用

EXP125保留普通半长复数分解，在末段把镜像行放进同一块。最后一次FFT本来就要把输出放进共享存储，后处理直接读两侧，配对后写半谱。相位表按实际线程消费顺序排列，末段FFT结束后提前读齐每线程所需的两项或四项系数，不让这些值跨越FFT寄存器高峰。

当前版先把每列解释为一个2C点局部实数变换，在列FFT出口组合a与C−a；端点打包进第零行。普通行在入口乘周期N相位，做Q点FFT，再折叠共轭写出。第零载体行另用一次Q点FFT加局部后处理恢复端点频率。它不要求镜像行同块，因此能覆盖奇数行长、奇数列长、奇数行槽和尾块。

这是一种不同的后处理分解，不是把EXP125的长度门槛放宽。

### 列端增加共享交换和同步

原列端输出本来在寄存器，通常直接乘相位并写中间矩阵。当前列端必须先交换镜像数据：完整容量写复数再读；半容量先写实部、保存配对实部，再写虚部并读取。因此需要额外同步和暂存。

例如128K列端共享读取静态指令36→50、共享写入33→44；旧设备计数共享操作8960→11840。该列端源码与当前版只差版本名称，本轮逐项核对五尺寸、双向共十份列源码一致。旧计数器可以佐证这段相同代码增加交换，但旧运行的耗时不冒充本轮当前版耗时。

### 大相位从列出口移到行入口，原有两项机制没有转移

EXP125列端已有大相位递推：一组输出先查初值和步长，后续系数由短乘法链得到。256列和1024列还会在FFT数据共享区失效后复用该区，装入相位表再使用。

当前`StockhamKernelFoldedSpectrumRows::input_value`对每个普通行元素独立调用`TW_NSteps`，再读取信号并相乘；没有沿用列端的递推和共享表驻留。读取进入FFT输入依赖链，Q=512的部分线程有效布局又曾被整行分类改写影响了请求安排。

|---:|---:|---:|---:|
| 65536 | 32768 | 32512 | 0.992 |
| 131072 | 16384 | 65280 | 3.984 |
| 262144 | 32768 | 130560 | 3.984 |
| 524288 | 65536 | 261632 | 3.992 |
| 1048576 | 163840 | 523776 | 3.197 |

这是依照生成循环和有效线程计算的查询求值数，不是显存请求数。旧版有共享表驻留和缓存复用；当前每次查询读取两段或三段小表，不能拿此比值声称显存流量增加四倍。128K还从周期N/2的两段表变为周期N的三段表。64K是重要例外：它没有丢失旧递推，主要变化是旧共享表和后处理流水被新边界流水替代。

旧后处理表虽为N/4个复数、随N增长，但按线程顺序连续读取，并且在FFT之后预取。当前小表的唯一容量小得多，这是资源优势；创建表、分配表的时间不在当前正式FFT计时窗口内。小表更小不等于依赖链更短。已有128K行端读请求24732→16726，却仍变慢，正说明不能只用读请求量解释耗时。

### 第四版修了调度的一部分，没改上述列端和查询数量

961591中，只恢复输入就能使262144点第三版37.60→35.12微秒、一兆76.56→71.60微秒；只恢复输出无相同改善。读取请求、临时内存、工作组驻留上限没有相应恶化，定位到输入代码安排。

第四版按首轮部分线程有效的布局实行双寄存器分组。979273同轮对照中，262144点37.60→34.24，524288点47.84→44.32，一兆75.52→69.76微秒。它对第三版有实际改善，但没有去掉列端两轮交换，也没有减少普通行独立大相位查询。不能把第四版仍残留的退化继续全部归于已经修过的整行输入分类。

## 5. 可实施的通用改法及其代价

### A. 前处理输出：生成时分清完整成对行块

修改`stockham_gen_cc_real_rows.h`的`StockhamKernelPackedInverseRows::store_to_global`。当`C%2==0 && R%2==0 && C%R==0`，直接生成：

```cpp
slot = tid % R;
component = slot / (R / 2);
pair = slot % (R / 2);
j = tid / R + iteration * threads_per_transform;
value = {lds_real[2 * (2 * pair * Q + j) + component],
         lds_real[2 * ((2 * pair + 1) * Q + j) + component]};
output[block * (R / 2) + pair + C * j + component * (C / 2)] = value;
```

若Q不能整除每行线程数，仅最后一轮保留频率尾部判断。其他几何保留当前通用写出；旧尺寸没有单独门槛。初版不改变输入、相位、端点打包或FFT主体。

正确性依据是输出地址恰好对应相邻两行同一实／虚分量，全部标量各出现一次。现有283种登记几何中107种满足条件，已对首末行块验证地址和值的对应；包括奇数Q。七个代表尝试中六个实际符合条件，均编译通过。旧五尺寸的整核静态指令从1021／845降为720／687，无新增全局访问、同步、临时数组或寄存器需求。这里是编译结果，尚无新设备加速比。

这比让编译器猜测网格范围更直接，也保留了奇数列、奇数行槽和尾块的通用处理。

### B. 后处理行端：复用相位初值和步长

修改同文件`StockhamKernelFoldedSpectrumRows`的普通行寄存器输入，将原生首轮映射作为唯一位置来源。若首因子为f，K=Q/f，原位置为`j=lane+h*T+w*K`，则同一h内：

```cpp
delta = phase(row * K);
p = phase(row * (lane + h * T));
for_each_native_register(w) {
    value = load_same_input_position();
    R[reg] = multiply(value, p);
    p = multiply(p, delta);
}
```

步长跨h复用，初值按原h组计算。保留第四版载体行分支、双寄存器读取分组、有效线程与尾部保护，不预先保存整行系数。载体行不进入递推；端点、输出、表段数、边界表缓存身份保持原样。生成策略按可证明的原生映射和可节省的查询数选择，不列举N。

源码副本中十个代表涵盖二次幂、行长200／169／289／343／625及奇偶列。直接链和双步链共20份编译全部通过、无溢出。283种几何的21447个相位模型检查中，直接链与原分段查表最大差异2.23×10⁻¹⁵，双步链2.49×10⁻¹⁵；这是系数模型，仍须设备FFT数值验收。

代表代价：

| 代表行端 | 当前指令／寄存器 | 直接链原型 | 观察 |
|---|---|---|---|
| 131072点d2z | 777／67 | 736／67 | 静态全局加载45→35；首同步前清空等待5→3 |
| 262144点d2z | 918／63 | 812／60 | 加载63→43；清空等待6→7，不能以等待条数承诺提速 |
| 524288点d2z | 917／63 | 811／60 | 同类查询减少，仍有递推依赖 |
| 一兆点d2z | 918／63 | 818／60 | 加载63→45；列端成本不变 |

额外开销是短递推的浮点舍入和串行依赖，以及步长、当前相位的生存期。双步链试图缩短依赖，但625点行会比直接链多12个寄存器需求；不把双步链无条件统一启用。直接链更适合作为首个受控候选，设备结果不佳时可恢复为独立查表。

### C. 后处理的结构性备选

若列端交换仍占主要增量，应比较“普通列FFT＋通用镜像行同块后处理”。这能够保留EXP125的列端相位递推及共享表，避免新增列配对交换，但会重新引入行块配对约束及全长后处理系数访问。它不能通过复制五个N的旧白名单解决。

可以先以C偶数、R偶数、C整除R为能力条件，复用旧的镜像行映射；将Q偶数限制推广为由实际频点所有权决定写出。Q奇数时，每对镜像行的低半区数量分别为ceil(Q/2)和floor(Q/2)，另处理直流、奈奎斯特及自镜像点。配对行槽不足、奇数列或资源不满足时，保留局部列后处理。

该方向需要同步修改`tree_node_real.cpp`、`real_block_io.h`、`stockham_gen_real_post.h`、`rtc_twiddle_gen.cpp`与资源缓存键，并证明每个行槽及半谱点的唯一所有权。它的实现面和验证面明显大于A、B，当前没有覆盖所有新奇偶组合的受控性能证据，因此本轮不把它当作已经就绪的默认替换。

## 6. 如何得到干净的下一轮结论

先用同一已验收当前库做运行时源码替换，分别比较原代码、仅A、仅B及两项组合。计时仍十次预热、三十次正式样本，同卡紧邻交替，中位数、不删点；校验和实际替换命中在计时外完成。覆盖五个旧N及同几何类型的非二次幂、奇数Q、奇数C、尾块和载体行；未满足A、B条件的路径检查源码与行为保持现状。无需为首次受控比较重复构建两份参考库。

另立计划归因对照：EXP125默认版；保留新CC分解表但关闭新通用融合、保留旧五尺寸融合的同源版本；当前通用融合版。先确认中间版本的普通内核及C、Q与预期一致，再将“原版→中间版”和“中间版→融合版”分别报告。若需要对旧五尺寸测量融合本身，再额外关闭其旧融合，不能把EXP125直接称为未融合版。

只有同CC计划对照才适合定量回答“融合贡献了多少”；已有跨路径总表回答的是整个版本快了多少。性能计数器应服务于受控后仍存在的具体差异，不需要先重复采集全矩阵所有指标。
