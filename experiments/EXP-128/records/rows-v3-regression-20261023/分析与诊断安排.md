# EXP128 行端简化退化：主机证据与设备诊断安排

对象为960099中相对通用融合v2低于0.95的全部24项。当前v3已保存于91b47a57及标签exp128-cc-row-simplify-v3-20261023；本轮只诊断，不修改生产实现。

## 已确认的事实

24项分属9种方向与行长类型。相同类型在不同列长、尾块及规模下也有改善或接近持平的组合，因此诊断保留全部退化项，为每个类型加入3个对照，另覆盖现有全部17个行长512的d2z尺寸及行长289、343的正向对照，共57个尺寸与方向组合。

主机检查重建了21ad4f809a3b的v2生成器，与已保存v3生成器使用相同原生规格。两版列端生成源码在全部选取几何及正常／回调形态中除版本名称外逐字一致；114份行内核分别离线编译成功。此为生成与编译证据，实际加载代码、资源与耗时由新诊断核对。

上述24项两版均未产生寄存器溢出，私有段大小均为零。尤其行长512的12项退化，向量寄存器由60降为59；个别同类型对照反而升至73，故不能把本类退化直接归因于寄存器增加或溢出。行长1331、1024的d2z寄存器有增加，需要核对加载后的资源容量与设备等待，不能借用512类结论。

以262144 d2z为例，静态指令总数1053→915，执行掩码／跳转指令83→41，全局加载指令63→57；双精度运算328、共享存储读22／写24及同步9均保持原计数。静态指令减少不能推出动态传输量减少，也不能推出延迟降低。

行端输入由每个展开项分别判断行类型，改成先区分整行再展开；输出由每个频点计算完整索引并分类，改成行槽与折叠条件提前。这改变了编译器的加载合并、指令排列和临时值存活范围。具体哪一项影响实际关键路径，需要隔离和设备数据证明，现阶段不将其指定为根因。

## 本次诊断

1. 复用960099的原始计时程序和两份已测安装。57个组合先作相邻、交替的v2／v3无分析器测量；24个退化组合在分析器工作后再反向顺序测量，核对漂移和进程先后效应。所有样本保留，仅用中位数。
2. 对57个组合的两版分别采集独立的计划／运行时编译源码记录与干净时间线；核对两个实际内核、默认加载路径、发射参数，将正式窗口分解为列阶段、行阶段和间隔。加载容量的最大驻留块数单独记录，不能把它写成实际占用率。
3. 对27个代表组合的两版采集通用指标与访存读取指标，保留原始字段、单位和最后30个实际窗口；重点比较行端等待、缓存、读写量、共享存储冲突及算术吞吐。设置／正确性与10次预热排除在统计外。
4. 在v3库内对10个组合隔离恢复旧输入、旧输出或两者；包含3个不同列长的512点行、其他退化类型及289点行对照。另有2个相同源码替换对照。每组前置相邻v2／v3控制，后置原v3控制；分析器不插入这组干净测量。
5. 对3个512点行的旧输入恢复额外采集运行容量与两种性能计数，用于核对输入分类是否影响关键等待。

输入／输出恢复只替换复制的运行时编译源码区域，校验相同接口、原生寄存器映射与精确来源；包括回调形态的56份原型已通过离线编译。20份完整行恢复与旧v2源码除名称外逐字相等；数据地址、直流、奈奎斯特和尾块处理由恢复区域整体保留。设备端仍用原程序严格数值检查并记录替换命中。

诊断共567次变换程序执行：普通前后测量162次、原版元数据114次、干净时间线114次、性能计数114次、恢复及相同源码对照30次、恢复元数据3次、相邻恢复控制30次。分析器结果只用于解释，不覆盖960099正式性能。所有独立失败汇总到同一记录。

不重建FFT库，不固定单节点，排除此前未识别到显卡的a01r4n05，开跑核对单卡gfx936并全程保持同卡。原始计时、源码、指标与失败证据按本轮实验目录保留。

## 判定与后续修改边界

若恢复旧输入能在多个列长上同步恢复行阶段耗时，且旧输出恢复不能复现，则将改善点限定在通用输入生成与调度；反向结果则限定在输出分类和折叠生成。两者共同影响或仅组合恢复有效时，检查跨阶段存活范围和调度耦合。不得只按N写特例。

若离线寄存器增加没有降低实际加载容量，或时间差落在列阶段／间隔，则不能继续用占用率解释；若新旧干净测量反转或明显漂移，先标出该证据限制。逻辑访问、静态指令、实际传输和等待分别统计。

后续方案必须以可复现的阶段差异和受控恢复为依据，覆盖对应原生行映射、奇偶和尾块，并同时计入新增判断、载入、寄存器、同步及代码生成复杂度。本轮生产代码保持已保存版本，任务提交后停止。
