# EXP128：回调修复及五分钟回归入口

用户于2026-10-21要求：修复重提，设备验证压缩到五分钟以内，删除没有必要的重复检查。随后用户强制规定今后每轮设备验证总时长不超过十分钟，本轮仍维持五分钟。此要求替代本轮原先的完整内部组合验收门槛；稳定分支、标签及EXP125对照安装不变。

## 问题与修改

952457先完成193个尺寸的620项公开接口记录，随后在65536点复数转实数的读取回调检查失败；952458依赖取消，正式性能没有运行。问题在保留的EXP125折叠列路径：零列和末列的镜像位置会重复读取同一个半谱元素，回调因此执行两次。尚未对EXP125原安装做设备复现，不将推断写成已经实测。

`StockhamKernelHermitianColumns`复用新增折叠列加载器的边界缓存。每个物理输入只调用一次回调，随后按镜像复用返回值并共轭。保留原有完整行距、中间矩阵、普通输出和大旋转因子语义；只为回调变体启用直接寄存器入口并增加独立名称。缓存复用已有共享存储，增加两次块同步；默认不带回调的路径保持原生成语句。

改动涉及`stockham_gen_local_real.h`、`stockham_gen_cc_real_columns.h`、`rtc_stockham_gen.cpp`，按五种旧几何统一接入。必要主机检查为生成器目标编译、五种旧几何的回调源码编译，以及新增适配器和旧默认源码逐字比较。证据见`host-before.json`、`host-after.json`；未通过前不提交。

## 限时设备验证

入口为`validate_cc_local_fast.py`。独立进程组在290秒触发终止，最多两次各三秒清理，整体不超过300秒；超时为失败，不自动延长。

先执行65536点两个方向的双回调、仅读取回调、仅写入回调及普通模式，优先暴露此前的失败。随后检查65856、67600、69938、131072、100352、133100，每个尺寸两个方向、普通及回调模式。抽样覆盖列行奇偶、行尾块、两种加载后端、半容量列和长行；不宣称覆盖所有列长、行长或内部组合。

每项只用脉冲和随机输入、两种缩放、两轮执行，保留数值误差小于十亿分之一、输入不改写、保护区不越界、回调逐元素一次及生成计划身份检查。共32项记录、128组参考、256次变换；逐项记录墙钟耗时。删除旧入口的193尺寸全矩阵、279个内部组合、计时辅助程序及78次分析器追踪。

旧完整验证入口和证据作为历史原件保留，不再被新任务调用。193个尺寸的旧公开结果仅作为旧库证据，新限时入口不冒充完整内部验收。

## 提交和性能

通过统一入口提交一个候选构建及限时回归，性能仅依赖该候选任务成功，不依赖EXP125的新任务。实际内核生成代码改变，必须重新产生候选库；EXP125安装直接复用。提交配置、提交号和任务号见`submission.json`。

性能矩阵不缩水：193个尺寸、两个方向，与EXP125各测一组，共772个进程、23160次正式样本。沿用双精度、批量一、非原位、默认路径、10次预热／30次计时、中位数比较。每个性能进程在计时窗口外对自身尺寸和方向检查正确性，失败结果拒绝汇总。已有EXP125默认分解及二次幂融合保留，比较为版本整体差异。构建及正式测量时间不计入五分钟验证上限。提交后停止，等待用户检查。
