# 通用 CC 路径改为 SBRC 行内前处理：评估与具体修改方案

2026年10月20日。核对服务器当前提交 `764dedde0c0524135b0ff32db71ef2423ea549a0`，只评估一维、双精度、批量一、非原位、连续输入输出、偶数 `N>65536` 的复数转实数（z2d）CC 路径。保留当前实数转复数（d2z）、转置、卷积及旧五尺寸实现。本轮没有修改生产代码、读取排队任务结果或提交设备任务；仅保存源码证据、执行主机模型及离线编译小原型。

## 建议

可以实施，而且有针对整类问题的优化机制。推荐采用：**折叠列变换＋中间端点打包＋通用行内前处理＋按地址配对写出**。不把原前处理调用直接移到末段，也不把已有二次幂生成器的尺寸限制直接放开。

与旧逐行方案相比，本方案进一步把每行两个实数端点放进一个复数槽，中间矩阵仍为 `C×Q`，无需扩大为 `C×(Q+1)`，也不要求行数、每块行槽为偶数。共享存储入口覆盖全部已登记列／行组合；满足线程交换条件的类型可使用寄存器入口。类型选择依据因子、线程映射、槽数和资源能力，不以具体 N 列白名单。

**数学、地址及最小写入原型已经成立；完整生成代码、设备正确性及净收益仍需实现后验证。** 当前证据支持建立候选，不支持承诺所有类型都会提速或直接替换稳定版。

## 一、当前实现与目标的区别

记 `M=N/2=C×Q`。C 为首段每列复数变换长度，Q 为末段每行复数变换长度。用户输入为 `H[0…M]`。

当前通用实现是：

`半谱 → SBCC 入口全局镜像配对前处理 → C 点列变换 → C×Q 中间矩阵 → Q 点 SBRC → 实数输出`。

首段为确保镜像列同块，需要偶数列槽和共享交换；`IsGenericPair()` 还会关闭若干已有核心优化。两种交换候选都没有消除这项入口通信，标量交换主要减少容量，增加同步。

旧五个二次幂尺寸采用另一种分解：先生成各行的局部半谱，再在 SBRC 行内前处理。其首段逻辑长度是 `{C,Q+1}`，输入步长为 `{2Q,1}`，大旋转因子周期为 N。当前通用 SBCC 的大旋转因子周期则为 M。两者的首段输出含义不同。

因此，“首段保持原样，只在 SBRC 加一遍当前前处理”不成立。含有随频点变化的旋转相位的前处理，不能与首段列变换直接交换次序。

## 二、分解、端点打包与正确性

将物理半谱扩展为逻辑共轭对称谱：

\[
\widetilde H[k]=\begin{cases}H[k],&k\le M,\\\overline{H[N-k]},&k>M.\end{cases}
\]

原始零频及奈奎斯特端点的虚部按现有复数转实数语义忽略；有加载回调时，先对物理输入执行回调，再完成端点处理及共轭。

首段对 `b=0…Q` 分别计算：

\[
V[s,b]=e^{2\pi i sb/N}\sum_{a=0}^{C-1}\widetilde H[2Qa+b]e^{2\pi i as/C},\qquad 0\le s<C.
\]

对每个 s，它是长度 `2Q` 的局部实数逆变换半谱，满足：

\[
V[s,2Q-b]=\overline{V[s,b]},\qquad V[s,0],V[s,Q]\in\mathbb R.
\]

这一关系对 C、Q 的奇偶都成立。它使端点可以采用如下物理布局：

```text
T[s,0].实部 = V[s,0].实部
T[s,0].虚部 = V[s,Q].实部
T[s,b]      = V[s,b]，1 ≤ b < Q
```

每行恰好 Q 个复数。首段仍要计算 Q+1 列，但端点各写一个双精度实数，合起来占一个复数槽。两个端点由不同工作组写入同一槽的不同 8 字节分量，地址不重叠，不需要原子操作。末段在首段整个内核结束后才读取，不存在提前读取另一工作组尚未写完的端点。

离线编译到本设备架构后，端点原型使用 `global_store_dwordx2`，即 8 字节写入；普通复数原型使用 `global_store_dwordx4`，即 16 字节写入。没有邻分量读取、整槽读改写或原子指令。**实际生成器也必须使用同样的实数写访问器，不能用整复数赋值覆盖端点槽。**

SBRC 入口从 T 恢复 Q 点复数逆变换输入 Z：

```text
Z[0] = {T[0].实部 + T[0].虚部，T[0].实部 - T[0].虚部}
对 1 ≤ j < Q-j：
    用现有配对公式一次生成 Z[j] 和 Z[Q-j]
仅当 Q 为偶数：
    Z[Q/2] = {2*T[Q/2].实部，-2*T[Q/2].虚部}
```

配对相位为周期 `2Q` 的相位，沿用当前公式的符号及缩放。相位表若以 j 直接索引，长度需为 `向上取整(Q/2)`；现有 `Q/2` 的向下取整只适用于已支持的偶数 Q，不能直接用于奇数 Q。

Q 点复数逆变换结果记为 Z 的逆变换 z，则最终位置为：

\[
x[s+C(2p)]=\operatorname{Re}z_s[p],\qquad
x[s+C(2p+1)]=\operatorname{Im}z_s[p].
\]

这里输出的实部和虚部相距 C，不是最终相邻两个实数。这也是不能直接套普通复数 SBRC 写出的原因。

## 三、首段如何保持简洁及原有优化

采用普通 SBCC 的因子、每列线程数、槽数、核心共享布局及旋转计算，只增加三个边界适配：

1. 加载逻辑地址 `k=2Qa+b`，折叠为 `min(k,N-k)`；镜像数据在物理加载及回调之后取共轭。
2. 列数改为 Q+1，大旋转因子周期改为 N。
3. 输出端点写实数分量，内部列仍按普通复数写出。

普通中间块保留原写回；首、末两个含端点的块才进入端点写回分支。核心不读取“是否实数边界”来关闭异或地址重排、旋转递推或寄存器内交换。新角色也不能被归入当前 `IsGenericPair()`。

对首段已有复数写节点，可由局部语法树访问器取得当前列 b、输出行 s，统一转换成端点或内部列写入。内部列保留原节点；端点生成实数写节点。禁止通过字符串替换生成代码或绕过非原位访问器手工拼接输出指针。

周期从 M 变为 N 后，必须重新调用现有大旋转因子分解与资源检查。当前 81 项中，21 项从基数八的两段查表变为三段，另有 4 项从小基数三段变为基数八三段。不能把“恢复普通核心”理解成首段相位成本完全不变。当前三段编码上限为 `2^24`；超出其能力的未来尺寸应保留旧路径，或另行扩展相位实现，不能忽略异常后放行。

## 四、行内前处理的两个入口

### 共用共享存储入口

这是完整覆盖的基础后端，不要求 C、Q、槽数或每行线程数为二的幂。

工作组线程按线性任务分配本块所有有效行的配对，顺序读取本行 j 与 Q-j，生成两个结果，写到本行原有输入共享区。端点及偶数 Q 的中点单独处理。所有线程统一同步后，复用 `first_pass_io()` 按普通首轮顺序装入寄存器，读后再统一保护共享区复用。

```text
并行处理有效行的端点、普通配对和可选中点
块同步
按 first_pass_io 的映射：R[寄存器] = 共享区[行,首轮坐标]
块同步
执行原 Q 点变换
```

尾行只屏蔽加载和写出；块同步不能放到有效行条件内。首轮部分有效的寄存器按现有公共方法初始化和保护，避免将未定义值带入后续轮次。

普通 SBRC 本来就需要的输入共享交换应与本后端逐项比较，不能把全部行内共享读写都算成净新增。与此同时，也不能把首段消除的交换直接算作全流程净节省：实际还取决于原末段是否直接读寄存器、末轮是否需要共享暂存，以及本次选择的行内后端。

### 寄存器与波内交换入口

从首轮因子和 `first_pass_io()` 建立坐标到线程、寄存器的逆映射，验证镜像结果的生产者与消费者是否能在同一波内交换，再生成静态赋值及交换。不能沿用固定 `Q=256/512、首轮跨度64` 的映射。

当前 21 类行配置中，坐标模型表明只有行长 `17、50、64、128、192、256、512` 满足所检查的同波必要条件；其他类型需跨波共享交换。其中部分行长在 `N>65536` 的当前目录没有实际分解，不能据此算作已覆盖的公开计划。

同波只是必要条件，还须检查交换指令参与掩码、非二幂子组、寄存器编号、奇数首轮因子及尾部工作。镜像传送不能从未参加本条交换指令的线程读取。按生成期映射安排每个交换轮次；无法证明时自动使用共享入口，不强改槽数或另建尺寸特化。

相位先按一对数据所需范围加载和消费，临时 p、q、相位及另一结果在赋值后尽快结束生存期。旧 512 行的整组相位提前加载策略不自动推广到其他因子；是否采用由生成代码的寄存器和等待证据决定。

## 五、奇数行、奇数槽及尾块的输出

不为向量写出降低普通行槽数，也不强制最少两行同块。复用末轮已有共享结果，只把本工作组真正持有的相邻实数配成一次复数写；不完整的配对用单个实数写出。

设本块首行 `s0=块号×T`，有效行数为 V。对实、虚两个输出分量 `h=0,1`，分别计算：

```text
首个配对槽 = (s0 + C*h) 的奇偶位
配对起点   = s0 + 首个配对槽 + 2*槽号 + C*(2*p+h)
```

只有起点为偶数且两个相邻行都在本块时，才写一个对齐复数；首、尾剩余实数各有唯一写者。相邻位置若属于另一工作组，分别用实数写，不跨块读数据，也不增加中间重排内核。

完整块中配对数量可以在生成期确定：偶数 T、奇数 C 的虚部分量比实部分量少一对；奇数 T 的两种起点奇偶有相同配对数量。把奇偶公共计算放在块级，尾块单独屏蔽。`T=1` 时直接生成标量写出，不产生除零或空配对分支。

当前 81 项中，这种写法可让 39 项全部成对写出、23 项混合写出；19 项仍全部单实数写出，主要包含每块只有一行的类型。这 19 项是性能风险，不能靠静态地址正确就宣布提速。混合方案比“C 或 T 为奇数便全量标量写出”保留了更多向量访问，又不会改变块组织。

实现上保留普通 `StoreGlobal` 节点及缩放、非原位访问流程，增加仅供新边界使用的带类型写访问器：复数值的索引单位仍为复数；实数值的索引单位为实数。无回调时分别生成 16／8 字节写；有实数输出回调时，把复数写拆成两个正确实数偏移的回调，实数写只回调一次。访问器集中声明及类型转换，不把转换分散到蝶形或每个访存位置。

带类型访问器的小原型也已离线编译：无回调分支被内联，保留相应 8／16 字节写，没有函数指针调用。它支持这种接口写法，不代表完整内核的寄存器或性能已经验收。

## 六、回调和临时区的完整语义

折叠首段无回调时共加载 `M+C` 个复数，而物理半谱只有 `M+1` 个。重复仅发生于边界列 0、Q，共 C-1 次。

若有输入回调，边界必须采用唯一拥有者：

- 列 0：行 a 与 `(-a) mod C` 共享一次物理加载结果。
- 列 Q：行 a 与 `C-1-a` 共享一次物理加载结果。

每对只由较小行坐标加载、执行回调，将未经共轭的回调结果放入缓存的两个逻辑位置；消费时再按原逻辑坐标决定共轭。两个列合计唯一加载 C+1 个边界物理元素，内部列没有重复，因此所有 M+1 个物理输入恰好回调一次。该规则覆盖奇数 C。

首版给回调内核独立的 C 个复数边界缓存，避免缓存读者与普通共享入口写者互相覆盖。增加容量 `16C` 字节，增加填充后和读完后的保护同步；仅端点块实际使用，但容量预留会影响整个回调内核的并发，必须记账。当前目录 279 种组合中，两端位于不同块，含大旋转附加区及这份缓存的首段共享容量最大为 49152 字节，未超过登记的 65536 字节预算。未来几何若两端同块或资源不足，应按缓存能力处理或回退，不能假设永远符合当前目录。

中间矩阵物理视图必须登记为 `{Q,C}`、步长 `{1,Q}`、距离 M。首段的逻辑列数仍为 Q+1，不能用它推断物理输出大小。除 `GetPhysicalOutputBufferView()` 外，还要让实际工作区分配使用该视图；当前 `DetermineBufferMemory()` 仍直接按逻辑长度计算，不能漏改。禁止自动填充逻辑端点维度来破坏打包关系。用户输出仍为 N 个实数，即 M 个复数的字节容量；不能误登记成 N 个复数。

缓存、首轮共享区及末轮共享区的职责分开。中间区不清零，每个实际分量都有唯一写者且在使用前已写入；端点不靠读改写保存另一分量。

## 七、净收益与新增开销

以下为同一 C×Q 下的逻辑工作量，不是设备显存流量或耗时预测。

| 项目 | 推荐方案的变化 |
| --- | --- |
| 独立前处理调用 | 继续消除一次；相对当前融合没有再次减少调用 |
| 前处理结果数组 | 继续省去 `32M=16N` 字节全局写＋读 |
| 中间矩阵 | 打包后仍为 `16M` 字节，写读有效数据量均不增加 |
| 无回调输入 | 仅增加 `16(C-1)` 字节边界重复加载 |
| 首段列变换 | 从 Q 列变为 Q+1 列，列工作量增加 `1/Q` |
| 首段组织 | 恢复普通槽数、共享容量及可适用的核心能力 |
| 行内前处理相位表 | 由约 M/2 个复数降为 `向上取整(Q/2)` 个，所有 C 行复用 |
| 末段 | 增加行内配对；共享入口替换或增加相应入口交换；输出可能需单实数写 |
| 准备阶段 | 少建大配对相位表；需准备周期 N 的列相位及周期 2Q 的行相位，不计入逐次执行收益 |

当前 81 项中，额外无回调逻辑输入为 **944～16368 字节**，约占省去的前处理数组流量 **0.037%～0.499%**；首段列工作量增加 **0.075%～1.00%**。列工作量比例不能当作总变换耗时比例。

恢复普通列槽后，与当前同块配对首段相比，32 项工作组数量减少、35 项相同、14 项增加。增加通常来自 Q 恰好占满原块，而端点列另占一块；不表示内核算术增加同样比例。恢复槽数也可能增大单块共享容量，不能把块数减少直接解释成并行度提高。

预期更有利的类型是：当前配对导致槽数下降、完整复数交换占满共享存储、或核心优化被宽泛关闭的类型。寄存器行内入口还可能省掉末段原有共享暂存。

风险较高的类型是：每块一行、必须大量单实数写出、行内需要跨波共享交换、首段相位查表增加，以及输入回调缓存降低并发的类型。寄存器临时量、存储体冲突和实际事务合并必须从生成代码及设备证据检查，不能仅凭这些字节数定性。

旧展开布局可以作为调试参考，但不建议作为主候选。另需修正旧评估中的一种计数方式：**行距填充增加容量，并不自动增加同等逻辑读写量**；只有实际访问的填充元素才能计入流量，事务变化需另外测量。
